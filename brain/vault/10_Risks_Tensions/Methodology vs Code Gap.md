# Methodology vs Code Gap

The documentation debt discovered during the June 17 review: **the web tool's published methodology page describes methods the code does not implement** — and, more broadly, the project's fleet numbers come from a static division formula while the professional standard (and the tool's implied sophistication) is agent-based simulation ([[Wolfsburg Activity Map]], [[MIA Mobility Impact Analyzer]]).

The gap has two faces. The narrow one is fixable hygiene: align the methodology page with what the algorithms actually do, so no juror comparing text to behaviour finds daylight ([[Intermodal Hub Algorithm]]). The broad one is the honest limit of the toolchain: division is not simulation, and the difference is exactly why the tool and the documents disagree about the fleet total ([[Fleet Number Conflict]]).

The register's treatment turns both into strategy: state that the fleet figure is a **first-order analytical estimate**, cite MIA's MATSim-based Zurich study as external validation of the order of magnitude, and name the agent-based run as the roadmap's next step ([[VW Shift Wave Simulation]], [[MATSim]]) — rigour demonstrated through disclosure rather than claimed through polish ([[Risk — Fleet Math Challenged]]).
