# Session Memory System

The project's answer to a real constraint of AI-assisted work: **a working session's memory ends with the session**, so continuity must be engineered in files. The system: `CLAUDE.md` (the standing briefing, read first every session) → `HANDOFF.md` (where-are-we-now: state, deadlines, resume-here actions) → `sessions/INDEX.md` plus one dated log per session → `decisions.md` for anything formally locked → `notes.md` as scratchpad. End-of-session protocol: write the log, update the handoff, record decisions ([[Prove the System Decision]]).

The discipline has already paid for itself across usage resets and machine changes — the work survives because its state is always externalised. It is, structurally, a memory architecture: append-only history (sessions), mutable working state (handoff), and locked facts (decisions) kept in separate files with separate update rules.

This knowledge graph is the system's culmination: the same externalised project memory, atomised into ~500 linked notes and made explorable — the workflow's private continuity turned into the exhibition's public brain ([[Project Brain]], [[Summaery Exhibition]]).
